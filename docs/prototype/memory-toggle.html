3. 点了之后会发生什么本会话永久生效

记忆开启（默认）

  • 会话边界注入记忆快照（与现在完全一致）
  • memory_search / write / edit / archive / log 五个工具可用
  • 交付完成时照常提醒沉淀

记忆关闭

  • 不注入任何记忆内容（提示词里零痕迹）
  • 五个 memory_* 工具从本会话可见面消失
  • 其他工具（读写文件、bash…）完全不受影响
  • 开关状态只在本会话内有效，重启 DSH 后回到默认「开」
注：关闭是即时的——切换后的下一个模型 step 就生效，不需要新建对话。但已经写进历史的旧快照不会被抹掉（历史不可篡改）。

4. 为什么是这个位置而不是新建对话页的大标题区

候选位置可行性说明
conversation.input.left
工具行左侧分组末尾		 ✅ 推荐 list 槽，加式不抢位；新建对话与普通会话都渲染；自带 sessionId，能直接读写本会话状态；和 permission/plan 是同一行同一族控件，视觉自洽。
conversation.input.dock
输入框上方整宽		 ⚠️ 次选 也渲染、也能用，但整宽区域适合放「提示条」而非小开关，会显得比它承载的信息重。
新建对话页标题旁的 hero 槽
agentPreset / workspace 旁		 ❌ 不可行 三个 hero 槽全是 single 且已被 WorkspacePicker 与 agent-preset 占用；重复注册直接抛错，换优先级等于顶掉随附 UI。
记忆面板里加一个开关
conversation.view 那个「记忆」页		 ❌ 达不到目的 该槽在空白会话完全不渲染，新建对话时根本看不到；且面板是「查看」语义，放开关会混淆。

5. 待你拍板的两点

#选择我的建议
1 关闭时要不要保留文字（「记忆已关」）还是只留带斜杠的图标？ 保留文字。关闭是「静默失效」，必须让用户一眼看见，否则会误以为记忆还在工作。
2 关闭后，记忆面板那个「记忆」页签要不要一起隐藏？ 保留页签但显示一行「本会话已关闭记忆」+ 就地重新开启。理由：用户可能只是想确认，不该逼他回输入区找开关。
